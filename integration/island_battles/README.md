# Island Battles lobby integration

Run `./scripts/test-lobby-acceptance.sh` from the monorepo root. The script runs the shared `lobby/integration/run.py` runner against the Island Battles host and this suite, using the SDK's locked `integration` dependency group, which includes the generic lobby Python client. Shared lobby code stays unchanged.

These tests own game-specific assertions: generation one initializes on Island Battles lobby start; starting a started lobby again binds no second game; commands are authorized against the frozen roster and team ownership; roster players keep commands, state and the replay after their lobby is deleted; incremental batches and empty completed turns work; one player's completion waits for every roster player; final completion advances once and emits each player's next-generation event; rejected commands do not partially apply; a player who never plays makes their team lose at the turn deadline, which the waiting player's client applies; and other game keys create no Island Battles state. Generic lobby behavior is tested under `lobby/integration/`.

The HTTP and event contract, including request UUID retries, error statuses, reservations, disconnected-player waiting and client recovery, is documented in the [Issue #6 task plan](../../docs/tasks/issue-6-player-generation-commands.md). The gameplay SDK is documented in [`clients/island-battles-python`](../../clients/island-battles-python/README.md); its bots are functions from `BotTurn` to `BotTurnResult` that `IslandBattlesClient` takes as `play=`, as shown in the example.
