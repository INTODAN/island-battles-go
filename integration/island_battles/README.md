# Island Battles lobby integration

Run `npm ci --prefix clients/island-battles-typescript`, then `./scripts/test-lobby-acceptance.sh` from the monorepo root. The script builds the TypeScript SDK and runs the shared `lobby/integration/run.py` runner against the Island Battles host and this suite, using the SDK's locked `integration` dependency group, which includes the generic lobby Python client. Node 24 is required. Shared lobby test infrastructure stays unchanged.

These tests own game-specific assertions: generation one initializes on Island Battles lobby start; `/game/from-lobby` retries return the same binding; commands are authorized against the frozen roster and team ownership; incremental batches and empty completed turns work; one player's completion waits for every roster player; final completion advances once and emits each player's next-generation event; rejected commands do not partially apply; and other game keys create no Island Battles state. Previously saved spectator replays remain available. Generic lobby behavior is tested under `lobby/integration/`.

The suite also runs a Python and TypeScript player in the same real game: both generated HTTP boundaries complete the first turn, and both receive the same next generation over authenticated Centrifugo subscriptions. Their generic lobby clients remain running to own the leases. The test fails if Node or its built SDK is unavailable; it does not silently skip a language.

The [shared behavior specification](../../docs/sdk/behavior.md) and [conformance scenarios](../../clients/conformance/README.md) describe client behavior. Additional backend rules are documented in the [Issue #6 task plan](../../docs/tasks/issue-6-player-generation-commands.md). The gameplay SDK is documented in [`clients/island-battles-python`](../../clients/island-battles-python/README.md); its strategies subclass the abstract `Player` base class and use `player_factory`, as shown in the example.
